# Codingal Release Update

Use when user asks release update, launch update, or short post-release summary for team.

## Goal

Write short, sweet, non-technical release update about current PR or recent changes.

## Format

1. Start with `Release Update: [Brief title]`
2. Brief greeting announcing release.
3. `Key Updates:` section.
4. Main changes as bullets using `—`.
5. `Why:` section — short non-technical paragraph on problem or motivation.
6. End with short impact statement — hopefully students or users love changes.

## Style Rules

1. Concise, easy read.
2. Simple, non-technical language.
3. Benefits and improvements, not implementation details.
4. Excited, positive tone.
5. Max 10-12 bullets.
6. Prefer user-facing improvements over internal refactors.

## Working Notes

1. Request references PR? Use current branch PR context when available.
2. Change mostly technical? Translate to outcome-focused language.
3. Skip low-signal internal details unless they affect users or team operations.
